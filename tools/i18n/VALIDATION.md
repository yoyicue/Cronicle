# Cronicle r1 历史本地验收

当前 r2 的确切源码、Linux 运行及边界见 [Release 附件 VALIDATION.md](https://github.com/yoyicue/Cronicle/releases/download/zh-CN-v0.9.137-r2/VALIDATION.md)。以下保留 r1 的历史本地验收，不能代替 r2 的 Actions 报告。

完成时间：2026-10-20 08:04，Asia/Shanghai。结论：固定版本的源码门禁、单元、官方回归和三浏览器集成全部通过。

官方基线为 tag `v0.9.137`，提交 `34fbd63058ac9f121e76527fded7211b366b996d`。本分支基于正式 tag，仅增加汉化资源、工具、测试和文档，全部 93 个原有上游文件保持原样。

## 验证环境

宿主 Node 为 25.2.1，npm 工具入口、所有验证阶段和产物均使用工具自带的 Node 22.23.3。Playwright 固定 1.64.1，Caddy 固定 2.11.7，运行环境为 Apple M4 Pro、darwin arm64，Chromium 为 156.0.8078.4。本次没有验证其他操作系统或 GitHub Actions。

A 为官方英文，B 为接入展示助手的英文，C 为中文。三套实例使用独立目录、合成密钥和主机身份。HTTP、SMTP 和 Caddy 只监听回环，禁用 UDP 发现，任务只执行合成本地脚本。

## 边界与已知问题

本次只完成固定版本的本地验证，未重新部署任何线上环境，未执行 48 小时观察、真实多 worker 增删与重启、磁盘满、断电或其他平台验证。时间机器、链式重试、多标签过期与批量任务的全部组合没有穷举。

原退出流程显示登录页后延迟清理数据，用例等待原清理完成再登录。原 dist 复制竞态只在隔离构建进程处理，不进入运行服务。原 WebServer 的 stat/open 竞态由定向用例覆盖，部署应追加不可变目录与入口，保留原英文静态根。

未来上游或依赖漂移会使构建失败，必须重新审查清单并重跑验证。有限测试与源码保护不能证明所有环境、输入和未来版本绝无风险。
